Apps próprios no Goat Phone

O Goat Phone deixa você criar apps que aparecem na tela inicial do celular como qualquer app nativo: ícone, nome, pastas, busca e notificações. O app mora num recurso FiveM seu, separado do goat-phone. Você não mexe no código do celular e não perde nada ao atualizar.

O app é uma página web (HTML, CSS e JavaScript, com ou sem framework) que o celular abre dentro da janela do app. A página conversa com o celular pelo SDK goat-phone-sdk.js e com o seu próprio Lua pelos callbacks NUI do seu recurso.

sua página (iframe)  ──SDK──▶  Goat Phone  ──▶  notificações, câmera, contatos, GPS...
        │                          ▲
        └──fetchNui──▶ seu client.lua ──▶ seu server.lua ──sendAppMessage──┘

Começo rápido

  1. Copie examples/goat-phone-app-template para a pasta resources do servidor.
  2. Coloque ensure goat-phone-app-template no server.cfg, depois do ensure goat-phone.
  3. Entre no servidor e abra o celular: o app Modelo aparece na segunda página da tela inicial.

O template mostra todas as funções do SDK. Para criar o seu app, renomeie a pasta, troque o id e o nome em server.lua e edite os arquivos de ui/.

Estrutura de um app

meu-app/
├── fxmanifest.lua
├── server.lua        registra o app e guarda as regras
├── client.lua        callbacks NUI chamados pela página
└── ui/
    ├── index.html
    ├── app.js
    ├── styles.css
    ├── icon.png      ícone quadrado, de preferência 180×180 ou maior
    └── goat-phone-sdk.js

Todo arquivo que a página usa precisa estar em files no fxmanifest.lua. Não use ui_page: a página é aberta pelo celular, não pelo seu recurso.

fx_version 'cerulean'
game 'gta5'
lua54 'yes'

dependency 'goat-phone'

files {
  'ui/index.html',
  'ui/app.js',
  'ui/styles.css',
  'ui/icon.png',
  'ui/goat-phone-sdk.js',
}

client_script 'client.lua'
server_script 'server.lua'

Registrar o app

O registro é feito no servidor. Registre quando o seu recurso inicia e de novo sempre que o goat-phone reiniciar:

local function register()
  local ok, err = exports['goat-phone']:registerApp({
    id = 'meu-banco',
    name = { ['pt-br'] = 'Banco', en = 'Bank', es = 'Banco' },
    description = 'Saldo e transferências',
    icon = 'ui/icon.png',
    ui = 'ui/index.html',
    page = 2,
  })
  if not ok then
    print('app recusado: ' .. err)
  end
end

AddEventHandler('onResourceStart', function(resource)
  if resource == 'goat-phone' then
    register()
  end
end)

CreateThread(function()
  if GetResourceState('goat-phone') == 'started' then
    register()
  end
end)

Campos

CampoObrigatórioDescrição
idsim3 a 32 caracteres, só letras minúsculas, números e hífen. Não pode ser o id de um app nativo nem de um app de outro recurso.
namesimTexto ('Banco') ou tabela por idioma (pt-br, en, es). Sem o idioma do jogador, usa pt-br, depois o primeiro que existir. Até 40 caracteres.
uisimCaminho da página dentro do seu recurso ('ui/index.html') ou uma URL https:// completa.
iconnãoCaminho ou URL https:// da imagem do ícone. Sem ícone, o celular desenha um ícone genérico na cor iconColor.
iconColornãoCor do ícone genérico em #RRGGBB. Padrão #5E5CE6.
descriptionnãoTexto curto, até 120 caracteres.
pagenãoPágina da tela inicial onde o app aparece pela primeira vez (começa em 1). Depois o jogador move o ícone como quiser.
darkChromenãotrue quando o app tem fundo escuro fixo: a barra de status fica clara.
permissionnãoPermissão conferida pela bridge do framework (permissão do vRP; ACE ou grupos de admin no ESX e no QB). Sem a permissão, o app nem aparece. No modo standalone, apps com permission ficam escondidos.
allownãoFunção do seu recurso que recebe o source e devolve true para mostrar o app. Use para emprego, item, horário ou qualquer regra sua. Se der erro, o app fica escondido.

O retorno é true ou false, codigo:

  • invalid_app: algum campo inválido (o motivo mais comum é id com maiúscula ou espaço, ou ui com http://).
  • app_conflict: o id já é de um app nativo ou de outro recurso.

Registrar de novo com o mesmo id, pelo mesmo recurso, substitui a definição. Quando o seu recurso para, o app some sozinho da tela de todos.

Exemplo de app só para um emprego

allow = function(source)
  local Player = exports['qb-core']:GetCoreObject().Functions.GetPlayer(source)
  return Player ~= nil and Player.PlayerData.job.name == 'police'
end

A lista de apps de cada jogador é recalculada toda vez que ele abre o celular. Se o emprego mudou com o celular aberto e você quer atualizar na hora, chame exports['goat-phone']:refreshApps(source).

Mensagens chegam à página só quando o app está aberto. Para dados que precisam estar lá ao abrir, a página pede ao seu Lua assim que carrega (veja counter:get no template).

SDK da página

Inclua o SDK antes do seu script:

<script src="goat-phone-sdk.js"></script>
<script src="app.js"></script>

O SDK cria window.GoatPhone. Para TypeScript, copie também goat-phone-sdk.d.ts.

Ao carregar, o SDK já:

  • avisa o celular que a página está pronta (sem isso, depois de 10 segundos o celular mostra erro com botão de tentar de novo);
  • coloca data-theme="light" ou "dark" e a classe dark no <html>, e atualiza quando o jogador troca o tema;
  • define --goat-safe-top e --goat-safe-bottom, a altura da barra de status e do indicador inicial, para o conteúdo não ficar por baixo deles;
  • libera o teclado para a página quando um campo de texto ganha foco e devolve o controle ao jogo quando perde. Sem isso o personagem andaria enquanto o jogador digita.

Eventos

GoatPhone.on('theme', ({ theme }) => {})
GoatPhone.on('locale', ({ locale }) => {})
GoatPhone.on('message', ({ event, data }) => {})

on e onMessage devolvem uma função que cancela a inscrição.

Erros

Quando algo falha, a promessa é rejeitada com um GoatPhoneError que tem code:

CódigoQuando
not_activeo app não está na frente (celular fechado, bloqueado ou com a Central de Controle aberta)
invalid_requestparâmetro inválido, como texto vazio no toast
unknown_methodmétodo que esta versão do celular não conhece
unavailableo celular não conseguiu fazer a ação, ou a página foi aberta fora do celular
timeouto celular não respondeu em 15 segundos
try {
  await GoatPhone.toast('Salvo')
} catch (error) {
  console.warn(error.code)
}

Falando com o seu Lua

A página chama os callbacks NUI do seu próprio recurso:

const saldo = await GoatPhone.fetchNui('banco:saldo', {})

Exemplo com ox_lib para buscar o valor no servidor:

RegisterNUICallback('banco:saldo', function(_, cb)
  local saldo = lib.callback.await('meu-banco:saldo', false)
  cb({ valor = saldo })
end)

Responda sempre o cb, inclusive em erro, senão a promessa da página não termina.

Para o servidor avisar a página (pagamento recebido, pedido aceito), use sendAppMessage:

exports['goat-phone']:sendAppMessage(source, 'meu-banco', 'saldo', { valor = 1500 })
GoatPhone.onMessage('saldo', ({ valor }) => mostrarSaldo(valor))

Segurança

  • Trate tudo que vem da página como entrada do jogador. Valide no servidor quem pode fazer o quê; o allow só decide quem vê o ícone.
  • O celular identifica o app pela janela de onde a mensagem veio, não por um campo que a página informe. Uma página não consegue se passar por outra.
  • Contatos, fotos, câmera e localização só respondem com o app aberto e na frente.
  • Prefira os arquivos do próprio recurso. URL externa (https://...) funciona, mas depende de o site permitir ser aberto num iframe e deixa o carregamento sujeito à internet do jogador.

Testar no navegador

No repositório do celular, pnpm dev abre o celular em http://localhost:5180 com dados de exemplo, e o template aparece na segunda página. Edite os arquivos em examples/goat-phone-app-template/ui/ e recarregue o app. Fora do jogo, fetchNui rejeita com unavailable; o template mostra como simular a resposta nesse caso.

Perguntas comuns

O app não aparece. Veja o console do servidor: o goat-phone imprime app de <recurso> recusado: <codigo>. Confira também se o seu recurso inicia depois do goat-phone e se o allow devolve true para o seu personagem.

A página abre em branco ou com erro. Confirme que todos os arquivos estão em files no fxmanifest.lua e que os caminhos no HTML são relativos (app.js, não /app.js). Use F8 para ver erros da página.

Posso usar React, Vue ou Svelte? Sim. Gere o build com caminhos relativos (no Vite, base: './'), coloque a pasta gerada em files e aponte ui para o index.html dela.

O jogador anda enquanto digita. O SDK só reconhece input, textarea e elementos contenteditable. Campos desenhados de outro jeito precisam usar um desses por baixo.
